# 城市外语标识纠错平台

面向市民、志愿者、语言专家和标识设置单位的外语标识纠错系统：市民用手机浏览器拍照报错，平台围绕同一标识持续保存设置单位、现场版本、照片、语种、规范条款、纠错意见、专家审定与整改回执。

## 运行

```bash
npm start          # http://127.0.0.1:8080
npm test           # node --test
```

首次启动在 `data/` 下生成存储文件与演示账号（真实部署应替换为统一身份认证）：

| 角色 | 令牌 | 说明 |
| --- | --- | --- |
| 志愿者 | `volunteer-demo` | 对待处理标识提交建议译法 |
| 专家（英语） | `expert-en-demo` | 审定英语译法 |
| 专家（日语） | `expert-jp-demo` | 审定日语译法 |
| 专家（利益冲突） | `expert-conflict-demo` | 与市园林中心存在关联，审定会被拒绝 |
| 设置单位 | `unit-demo` | 市园林中心经办，可接受/申诉/上传更换证明 |
| 主管部门 | `supervisor-demo` | 合并候选裁决、复查办结、区域与专家资源统计 |

## 流程与约定

- **报错**：手机页面拍照后在本地画布遮蔽人脸/车牌再上传；服务器二次剥离 EXIF/文本元数据。位置按用户授权精度保留（exact/street/district/none），公众视图最多展示街道级。
- **去重**：相似照片（dHash 海明距离 ≤10）与邻近坐标（≤60 米）只生成合并候选，由主管部门裁决合并或保留，任何线索不被自动删除。
- **审定**：专家须语种匹配且与设置单位无利益冲突；单位可接受、申诉（回到专家复核）或上传更换证明，每次复查形成新的现场版本。
- **隐私**：举报人联系方式仅库内留存，不出现在任何 API 响应；举报人凭提交时下发的令牌查询自己线索的进度与最终规范译法。
- **统计**：主管部门按区域网格查看长期未整改（>30 天）、反复出错标识与各语种专家缺口。

`fixtures/sign-report.json` 展示标识、语种和位置授权的字段约定。面向公众的页面只能呈现获准公开的信息，内部联系方式不得出现在公开响应中。
