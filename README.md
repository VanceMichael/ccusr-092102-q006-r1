# 城市外语标识纠错平台（福州）

市民在街头发现外语路牌问题时，直接用手机拍照、选择**位置精度授权**并提交即可，无需判断该找哪所高校的志愿者。平台围绕**同一块标识**持续归集：设置单位、历次现场版本、照片、语种、规范条款、纠错意见、志愿者译法、专家审定与整改回执，并为外事部门提供防重复派发与监管分析。

零第三方依赖：仅使用 Node.js 内置模块（`node:http` 等）与原生手机浏览器能力（Canvas / Geolocation）。

## 运行

```bash
npm start          # http://127.0.0.1:8080
npm test           # 24 项单元 + 全流程接口测试
```

- 市民页面：`/`（`public/index.html`）
- 协同工作台：`/console.html`（志愿者 / 专家 / 设置单位 / 主管部门，顶部一键切换演示账号）

## 业务流程

```
市民拍照 → 本地遮蔽人脸/车牌 → 按授权精度保存位置 → 线索进入甄别
        ↓
系统按 图片指纹(dHash) + 邻近坐标(仅在双方授权精度内) + 标识文字 → 提出“合并候选”
        ↓                               （只提议，绝不自动合并或删除）
外事部门人工判定 merge / separate → 确认非重复后才允许分派设置单位
        ↓
志愿者提出译法 → 符合语种且无利益冲突的专家审定（不能自审、不能审定本单位关联译法）
        ↓
设置单位 接受 / 申诉（主管裁决）→ 上传更换证明
        ↓
主管部门现场复查（每次复查产生一个新的现场版本）
   ├─ 通过：状态置“已整改规范”，规范译法向公众发布
   └─ 不通过：形成新版本、退回次数 +1、重新办理
        ↓
市民凭一次性“查询号”查看本人线索的办理时间线与最终规范译法
```

## 隐私边界（关键约束）

| 信息 | 市民本人 | 其他公众 | 志愿者/专家 | 设置单位 | 主管部门 |
|---|---|---|---|---|---|
| 线索状态 / 已发布规范译法 | ✅（仅本人线索全量时间线） | ✅ 摘要 | ✅ | ✅（本单位） | ✅ |
| 纠错意见、规范条款、现场照片 | ✅ 本人 | ❌ | ✅ | ✅（本单位） | ✅ |
| 精确坐标 | 按本人授权精度 | ❌ | 仅模糊点 | 不超过举报人授权精度 | ✅ |
| 举报人联系方式 | ✅ 本人 | ❌ | ❌（仅显示“是否已留”） | ❌（仅显示“是否已留”） | ✅ |
| 单位申诉措辞等内部意见 | ❌ | ❌ | 办理所需范围 | 本单位 | ✅ |

- 照片**只保存遮蔽后的版本**：手机端编辑器将人脸/车牌区域烧录为马赛克后才上传，服务端不接收原片；照片接口按角色与本人一次性令牌授权（`<img>` 使用 `?t=` 令牌）。
- 位置“不保留”时，任何坐标（含标识层聚合位置）都不落库；选择模糊精度时先在服务端按网格吸附，精确点不入库。
- 公开进度不携带任何举报人标识；监管分析输出为聚合数据（长期未整改、反复出错单位、专家资源不足的区域×语种），无个人字段。
- 合并是**归集标记**：源标识置 `merged` 并指向目标，线索与现场版本完整保留，可随时追溯，删除操作在系统中不存在。

## 接口一览

| 方法 | 路径 | 角色 |
|---|---|---|
| POST | `/api/reports` | 匿名市民（返回一次性 `track_token` 与合并候选提示） |
| POST | `/api/track` | 凭 `track_token` 查本人进展 |
| GET | `/api/volunteer/queue` / POST `/api/signs/:id/proposals` | 志愿者 |
| GET | `/api/expert/queue` / POST `/api/proposals/:id/review` | 专家（服务端强制语种匹配 + 利益回避 + 禁止自审） |
| GET | `/api/manager/queue` | 设置单位（仅本单位） |
| POST | `/api/signs/:id/respond`（accept/appeal）、`/proof` | 设置单位 |
| GET | `/api/admin/merge-candidates`、POST `.../:id/decision` | 主管部门（merge/separate） |
| POST | `/api/signs/:id/dispatch` | 主管部门（有未决候选时 409 拦截） |
| POST | `/api/signs/:id/appeal-decision`、`/recheck` | 主管部门（复查必传新现场照片，生成新现场版本） |
| GET | `/api/admin/analytics`、`/api/admin/orgs` | 主管部门 |
| GET | `/api/photos/:id` | 按角色 / 本人 `?t=` 令牌授权 |

## 目录

```
src/domain.js   领域规则：精度模糊、dHash/邻近候选、专家资格、状态、角色化隐私投影、监管分析
src/store.js    内存存储与演示种子（6+ 个覆盖各状态的标识，含待甄别候选）
src/server.js   HTTP API 与静态页面（含照片访问授权、路径穿越防护、15MB 请求上限）
public/         手机端上报页（含本地遮蔽编辑器）与四角色协同工作台
fixtures/       字段约定样例（不含真实个人信息）
test/           领域规则 8 项 + 接口全流程/隐私 15 项 + 原始契约 1 项
```

说明：当前存储为进程内内存，便于演示与测试；生产部署可在不改动 `domain.js` 规则的前提下替换为数据库，并为照片增加服务端二次遮蔽校验。
